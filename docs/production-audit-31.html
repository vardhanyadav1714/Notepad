Functionality and Google Play readiness

Release decision: do not publish publicly yet. The scoped local verification below has completed; untested device and distribution scenarios remain explicit. Privacy and support links have been added from the public listing, but the policy contents could not be retrieved and require review. The listing declares no collection and Families participation; both need reconciliation with this release. Backend changes have only been tested locally. Scope and reference evidence

The app is the Kotlin/Compose project in AndroidStudioProjects/Notepad. The supplied apktool and rea repositories are inspection tools. Apktool decoded the supplied Samsung Notes 4.4.13.5 manifest for this review. Existing focused JADX output was also inspected. REA's saved package-inspection result reports a missing Windows native manifest; no successful REA run or complete Samsung feature parity is claimed. Reference files stay outside the app source and packaged resources.

Confirmed defects corrected

  • Checklist content loss: checklist text and formatting now serialize into Room, and newly created content is immediately searchable.
  • PDF records erased by ordinary saves: retained note blocks are upserted, rather than deleted and recreated. Their PDF page/annotation records survive; removing a block still removes its dependent rows.
  • Drawing attachment replaced other blocks: adding a drawing now preserves existing content.
  • Tag lookup always empty: the repository now collects its query; creation and linking are transactional to avoid duplicate-name races.
  • FTS syntax and prefix handling: user terms are tokenized and quoted as literal prefixes, including words such as AND, rather than interpreted as query operators.
  • Interrupted or concurrent drawing saves: synchronized AtomicFile reads/writes preserve the last complete document and recover interrupted writes.
  • Recorder resource leaks: microphone setup failures release the recorder and remove incomplete recordings.
  • Collaboration malformed inputs and lost persistence: invalid JSON shapes, null points, malformed room URLs, and oversized updates are rejected. Strokes are stored transactionally before broadcast; storage errors reach the client. A full room rejects extra ink instead of silently dropping earlier strokes. A disconnected socket no longer stops delivery to others.

26 JVM tests passed. Android instrumentation reported 73 entries: 72 passed, one opt-in paired-device collaboration test skipped, zero failures. Worker typechecking and eight regression tests passed. A real local workerd test passed paired clients, 20 simultaneous additions, fresh-client recovery, page/stylus metadata, malformed-message recovery, and whole-canvas edit persistence. Release lint reported zero errors, 65 warnings and three informational findings. The final signed release passed all seven UI smoke checks, including live room connection/reconnection, two-page save/reopen and Settings links. Signed-release audio checks also passed. Actual handwriting-model download, recognition and insertion passed on the final signed release.

Evidence: signed-release UI results; recording and recognition results; release lint. Earlier probe failures included a permission-dialog script bug, an unconnected emulator network and concurrent UI-automation inspection; these were test-environment issues, not counted as passing app checks.

Android instrumentation ran on the isolated NotesReview emulator, Android 17 / API 37.1 with 16 KB pages. An attempted Android 10 emulator could not start because the installed SDK image directory contained only installer metadata; no Android 10 runtime results are claimed.

Google Play actions before publication

  1. Review and publish an accurate privacy policy. Settings now links to the policy listed on Google Play and public support email. The policy could not be retrieved during this review; its availability and contents remain unverified. A replacement draft with explicit unresolved decisions covers recordings, optional ink collaboration, retention, Android backup and SDK handling. Google Play User Data policy.
  2. Resolve the intended audience and Families safeguards. The supplied listing declares Families participation. A 3+ content rating is separate from target age groups. If children are in the intended audience, review shared drawing under the Families social-feature requirements, including safety reminders, adult management and adult action before personal-information exchange. The reviewed app does not yet implement these safeguards. The owner confirmed that every age group is selected (5 and under through 18 and over), with Teacher Approved review participation. The release direction for sharing is pending; no audience change has been made. Families policy.
  3. Review Data safety against the shipped dependencies. Local notes do not imply zero data collection: collaborative ink leaves the device, and ML Kit documents diagnostic, application/device, installation identifier, performance and configured-language data. The backend's hosting logs/settings also need owner verification. ML Kit disclosure guidance; Data safety guidance.
  4. Use Drawly's own identity and truthful feature claims. The app is branded Drawly; the reviewed source contains no Samsung package dependency or visible Samsung branding. This is not a legal provenance audit of every asset. Do not imply Samsung affiliation or advertise unsupported Samsung-specific features. Impersonation policy.
  5. Finish the backend release and real-device checks. Local worker changes need deployment and a paired-client smoke test against the deployed revision. Resolve or clearly constrain collaboration conflict behavior before relying on it for important shared documents.
  6. Run Play's pre-launch report on the exact uploaded bundle. Review crashes, ANRs, accessibility, device compatibility, target audience, content rating, app access, signing and listing declarations. These account settings were not accessible in this repository. Pre-launch report; Functionality policy.

Technical references

Audience measurement: no age analytics was found in the app. Existing downloads and reviews do not establish users' ages. Standard Play app-statistics dimensions do not provide a general age breakdown. The Play Age Signals API can support age-appropriate experiences where signals are available, but its terms prohibit analytics and profiling. It is not a retrospective age-demographics report. Unknown ages also need an appropriate safe experience. The recommended product direction is to keep local drawing available and introduce parent-managed online sharing; this direction has not yet been selected or implemented.

Candidate artifacts: signed APK and signed AAB. SHA-256 hashes; native alignment evidence. These are review candidates, not approved public releases.

AtomicFile requires caller synchronization, which the drawing storage now provides. Android AtomicFile. FTS4 prefix terms are quoted with the wildcard inside the phrase. SQLite FTS3/FTS4. The worker uses SQLite-backed Durable Objects and caps updates below the documented per-value bound. Durable Objects limits.
